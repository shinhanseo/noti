# 중요도 판정 정책

## 목표

`noti.`는 사용자가 직접 설정한 중요 앱과 키워드를 가장 우선하고, 그 외 알림은 설명 가능한 규칙으로 중요도를 판정한다.

MVP에서는 규칙 기반 판정을 먼저 구현한다. 경량 온디바이스 모델은 규칙만으로 판단하기 애매한 알림을 보조하는 용도로 이후 도입한다.

모든 판정은 다음 원칙을 지킨다.

- 사용자 설정은 자동 규칙과 온디바이스 모델보다 우선한다.
- 모든 중요 판정에는 최소 하나 이상의 사람이 이해할 수 있는 이유가 있어야 한다.
- 같은 입력과 같은 정책 버전은 항상 같은 결과를 반환해야 한다.
- 알림 제목과 본문은 판정을 위해 기기 내부에서만 사용한다.
- 정책의 점수와 경계값은 초기 가설이며 테스트와 사용자 피드백을 통해 조정한다.

## 정책 버전

초기 정책 버전은 `1`이다.

점수, 경계값, 매칭 방식 또는 우선순위가 변경되면 정책 버전을 올린다. 판정 결과에는 정책 버전과 판정 시각을 함께 저장해 기존 알림을 재평가할 수 있어야 한다.

```text
policyVersion = 1
```

## 입력 데이터

정책 v1은 현재 `NotificationItem`에서 제공하는 다음 값만 사용한다.

- 패키지명
- 제목
- 본문
- 게시 시각
- Android 알림 카테고리
- 진행 중 알림 여부

발신자와 최근 반복 문맥은 현재 안정적으로 추출하거나 비교할 수 없으므로 정책 v1에서 제외한다.

## 사용자 설정

정책 v1에서 사용자가 설정할 수 있는 값은 다음과 같다.

### 중요 앱

사용자가 중요 앱으로 선택한 앱의 알림은 기본적으로 `중요`로 분류한다.

앱은 표시 이름이 아니라 Android 패키지명으로 식별한다.

### 중요 앱별 제외 키워드

중요 앱에서 온 알림이라도 해당 앱에 설정한 제외 키워드가 포함되면 `일반`으로 분류한다.

제외 키워드는 특정 중요 앱에만 적용된다. 일반 앱을 `항상 일반`로 지정하는 기능은 정책 v1에서 제공하지 않는다.

### 전역 중요 키워드

전역 중요 키워드는 앱과 관계없이 적용한다. 일반 앱에서 온 알림이라도 전역 중요 키워드가 포함되면 `중요`로 분류한다.

## 판정 순서

알림은 다음 순서로 판정한다.

1. 수집 단계에서 자기 앱 알림, 그룹 요약, 빈 알림을 제외한다.
2. 제목과 본문을 판정용 텍스트로 정규화한다.
3. 중요 앱별 제외 키워드를 검사한다.
4. 전역 중요 키워드를 검사한다.
5. 중요 앱 여부를 검사한다.
6. 사용자 강제 판정이 없다면 자동 규칙 점수를 계산한다.
7. 점수를 등급으로 변환하고 판정 이유를 생성한다.

우선순위는 다음과 같다.

```text
현재 알림에 대한 사용자의 직접 수정
> 중요 앱별 제외 키워드
> 전역 중요 키워드
> 중요 앱
> 자동 점수
> 향후 온디바이스 모델 보조 점수
```

중요 앱별 제외 키워드는 특정 앱에 한정된 가장 구체적인 설정이므로 전역 중요 키워드보다 우선한다.

## 사용자 강제 판정

### 중요 앱별 제외 키워드가 매칭된 경우

점수를 계산하지 않고 `일반`로 분류한다.

```text
score = -100
level = GENERAL
forced = true
```

이유 예시:

```text
이 앱에서 제외하도록 설정한 표현이 포함됐어요
```

### 전역 중요 키워드가 매칭된 경우

점수를 계산하지 않고 `중요`로 분류한다.

```text
score = 100
level = IMPORTANT
forced = true
```

이유 예시:

```text
앱과 관계없이 중요하게 설정한 단어가 포함됐어요
```

### 중요 앱에서 온 경우

앱별 제외 키워드가 매칭되지 않았다면 `중요`로 분류한다.

```text
score = 100
level = IMPORTANT
forced = true
```

이유 예시:

```text
중요한 앱에서 온 알림이에요
```

## 텍스트 정규화

제목과 본문은 다음 순서로 정규화한다.

1. `null`을 빈 문자열로 변경한다.
2. 제목과 본문을 하나의 판정용 텍스트로 합친다.
3. 영문을 소문자로 변환한다.
4. 앞뒤 공백을 제거한다.
5. 연속된 공백을 하나로 합친다.

동일한 규칙이 제목과 본문에서 여러 번 매칭돼도 점수는 한 번만 적용한다.

## 자동 점수

사용자 강제 판정이 없는 일반 앱의 알림에만 자동 점수를 적용한다.

초기 점수는 `0`이며 최종 점수는 `-100`부터 `100` 사이로 제한한다.

### 긍정 신호

| 신호 | 점수 | 사용자에게 보여줄 이유 예시 |
|---|---:|---|
| 전화·알람 카테고리 | +40 | 바로 확인할 가능성이 높은 전화나 알람이에요 |
| 인증·보안 신호 | +30 | 인증이나 보안과 관련된 알림이에요 |
| 결제·계정·예약의 중요한 상태 변화 | +25 | 결제·계정·예약 상태가 중요하게 변경됐어요 |
| 긴급·즉시·마감 임박 표현 | +20 | 빠르게 확인해야 할 표현이 포함되어 있어요 |
| 날짜·시각·마감 표현 | +20 | 일정이나 마감 시간이 함께 있어요 |
| 제출·답변·회신·승인 등 행동 요청 | +20 | 확인하거나 처리할 요청이 있어요 |
| 일정·리마인더 카테고리 | +20 | 일정이나 리마인더 알림이에요 |
| 중요한 배송 상태 변화 | +10 | 배송 상태가 변경됐어요 |
| 일반 메시지·이메일 카테고리 | +5 | 메시지나 이메일 알림이에요 |

### 부정 신호

| 신호 | 점수 | 사용자에게 보여줄 이유 예시 |
|---|---:|---|
| 광고·혜택·이벤트·쿠폰·추천 신호 | -35 | 홍보성 알림으로 판단했어요 |
| 단순 다운로드·진행·서비스 상태 | -25 | 단순 진행 상태를 알려주는 알림이에요 |
| 별도 행동이 필요 없는 일반 상태 안내 | -10 | 별도 처리가 필요하지 않은 상태 안내예요 |

제목과 본문이 모두 없는 알림은 `NotificationFilter`에서 제외하므로 별도의 정보 부족 감점 규칙을 두지 않는다.

## 문맥 규칙

### 인증·보안

다음과 같은 표현을 하나의 규칙 그룹으로 평가한다.

```text
인증번호
보안 코드
로그인 시도
새로운 기기
비밀번호 변경
의심스러운 활동
```

여러 표현이 동시에 포함돼도 인증·보안 점수는 한 번만 적용한다.

### 행동 요청

단순 명사보다 요청형 문맥을 우선한다.

```text
제출해주세요
확인해주세요
답변해주세요
회신 바랍니다
승인이 필요합니다
서명해주세요
납부해주세요
```

`확인`처럼 광고에도 자주 등장하는 단어 하나만으로 행동 요청 점수를 주지 않는다.

### 날짜·시각·마감

```text
오늘까지
내일까지
오후 3시
10분 후
마감
기한
예정
시작합니다
```

날짜나 시각 표현 하나만으로는 중요 등급이 되지 않으며 다른 신호와 함께 평가한다.

### 결제·계정·예약 상태

`결제`, `계정`, `예약`이라는 단어만으로 점수를 주지 않는다. 상태 변화 표현과 함께 있을 때 적용한다.

```text
결제 + 승인/실패/거절/취소
계정 + 잠김/정지/변경
예약 + 변경/취소
```

### 홍보성 신호

```text
광고
혜택
이벤트
쿠폰
특가
할인
추천
프로모션
지금 구매
```

홍보성 신호가 있어도 사용자 강제 중요 판정이 존재하면 사용자 설정이 우선한다.

## 진행 중 알림

`isOngoing`이 `true`라는 이유만으로 감점하지 않는다.

다음 조건을 함께 만족할 때 단순 진행 상태 점수를 적용한다.

- 진행 중 알림이다.
- 카테고리가 다운로드, 진행, 서비스 또는 전송 상태에 가깝다.
- 전화, 알람, 보안, 긴급 또는 행동 요청 신호가 없다.

통화, 내비게이션 등 사용자가 즉시 확인해야 할 수 있는 진행 중 알림을 일괄 제외하지 않는다.

## 등급

| 총점 | 등급 | 처리 |
|---:|---|---|
| 40 이상 | `IMPORTANT` | 홈의 중요 알림 영역에 표시 |
| 20~39 | `REVIEW` | 전체 알림에 표시하고 사용자 판단을 수집할 후보 |
| 19 이하 | `GENERAL` | 전체 알림에 표시 |

사용자 강제 판정이 존재하면 등급표보다 우선한다.

## 판정 예시

| 알림 | 계산 | 결과 |
|---|---:|---|
| `오늘까지 서류를 제출해주세요` | 마감 +20, 행동 요청 +20 | 중요 40 |
| `결제가 실패했습니다. 확인해주세요` | 상태 변화 +25, 행동 요청 +20 | 중요 45 |
| `회의가 10분 후 시작됩니다` | 일정 +20, 시각 +20 | 중요 40 |
| `인증번호는 123456이며 3분간 유효합니다` | 보안 +30, 시각 +20 | 중요 50 |
| `오늘까지 사용할 수 있는 할인 쿠폰을 확인하세요` | 시각 +20, 행동 요청 +20, 홍보 -35 | 일반 5 |
| `택배 배송이 시작됐습니다` | 배송 +10 | 일반 10 |
| `새 메시지가 도착했습니다` | 메시지 +5 | 일반 5 |
| `회의 자료를 회신해주세요` | 메시지 +5, 행동 요청 +20 | 확인 필요 25 |
| `긴급: 회의 자료를 회신해주세요` | 긴급 +20, 행동 요청 +20, 메시지 +5 | 중요 45 |
| `파일 다운로드 중` | 진행 상태 -25 | 일반 -25 |

정책 구현 전후에 이 예시를 단위 테스트로 고정한다.

## 판정 결과

판정 결과는 최소 다음 정보를 포함한다.

```text
최종 점수
최종 등급
판정 이유 목록
사용자 강제 판정 여부
정책 버전
판정 시각
```

판정 이유에는 알림 제목이나 본문 전체를 복제해 저장하지 않는다.

```text
이유 유형
점수 변화량
사용자 규칙 ID
사용자에게 보여줄 설명
```

UI에서는 중요도에 영향을 많이 준 이유를 최대 1~3개까지 보여준다.

## 피드백 처리

### 중요 앱의 알림에서 `덜 중요해요`

현재 알림의 표현을 해당 중요 앱의 제외 키워드로 추가할 수 있게 한다.

### 일반 앱의 알림에서 `중요하게 보기`

다음 선택지를 제공한다.

- 이 앱을 중요 앱으로 추가
- 이 표현을 전역 중요 키워드로 추가
- 현재 알림만 중요하게 변경

### 일반 앱의 자동 오탐에서 `덜 중요해요`

일반 앱을 `항상 일반`로 지정하는 기능은 제공하지 않는다. 정책 v1에서는 현재 알림의 등급만 일반로 변경한다.

이후 유사 알림에도 반영하려면 다음 중 하나를 정책 v1.1 이후에 검토한다.

- 피드백으로 생성되는 앱별 제외 패턴
- 사용자별 자동 점수 보정
- 일반 앱에도 적용되는 제외 키워드

정책 v1에서는 사용자 피드백으로 자동 점수 가중치를 즉시 변경하지 않는다.

## 정책 v1에서 제외하는 항목

- 발신자 기반 규칙
- 짧은 시간 안에 같은 문맥이 반복되는 신호
- 사용자 피드백에 따른 자동 가중치 학습
- 서버 기반 AI 판정
- 온디바이스 모델의 실제 등급 반영

반복 문맥은 광고가 반복될수록 중요도가 올라가는 부작용을 방지하기 위해 비교 기준을 정의한 뒤 도입한다.

## 향후 온디바이스 모델

경량 온디바이스 모델은 사용자 규칙을 대체하지 않는다.

다음 조건에서만 보조 판정을 수행한다.

```text
사용자 강제 판정이 없다.
규칙 점수가 10~39점이다.
```

명확한 결과에는 모델을 실행하지 않는다.

```text
규칙 점수 40 이상 → 규칙 결과 유지
규칙 점수 9 이하  → 규칙 결과 유지
규칙 점수 10~39   → 온디바이스 모델 보조 판정 후보
```

모델은 중요할 확률을 `0.0`부터 `1.0` 사이로 반환하며, 결과를 제한된 보조 점수로 변환한다.

| 모델 중요 확률 | 보조 점수 |
|---:|---:|
| 0.80 이상 | +15 |
| 0.65~0.79 | +10 |
| 0.35~0.64 | 0 |
| 0.20~0.34 | -10 |
| 0.20 미만 | -15 |

모델이 실패하거나 사용할 수 없으면 규칙 점수만으로 판정한다. 모델 실패 때문에 알림 저장이 실패해서는 안 된다.

모델 도입은 다음 순서로 진행한다.

1. 규칙 기반 정책 v1과 단위 테스트를 완성한다.
2. 모델 결과를 저장만 하고 실제 등급에는 반영하지 않는 그림자 모드로 검증한다.
3. 사용자 피드백과 비교해 충분한 정확도를 확인한다.
4. 애매한 점수 구간에만 제한된 보조 점수를 적용한다.

모델이 관여한 경우에도 구체적인 판정 이유는 규칙 기반 이유를 우선한다. 모델이 설명하지 않은 내용을 사실처럼 생성하지 않는다.

판정 결과에는 향후 다음 모델 정보를 함께 저장할 수 있다.

```text
모델 중요 확률
모델 보조 점수
모델 버전
```

알림 제목과 본문은 모델 추론을 위해 기기 내부에서만 사용하며 외부 서비스로 전송하지 않는다.
