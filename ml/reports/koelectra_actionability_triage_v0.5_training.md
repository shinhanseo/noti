# KoELECTRA v0.5 3단계 Actionability 실험 결과

## 결론

`KoELECTRA-small-v3`를 TFLite로 변환해 온디바이스에서 실행하는 기술 경로는
확인했다. 그러나 현재 모델은 실제 Android 중요도 점수에 연결하지 않고 그림자
모드 후보로만 유지한다.

합성 데이터 5-Fold 결과는 양호했지만, 기존 Room 개발 세트에서 이 사용자의
중요/일반 선호와 크게 어긋났다. 다음 단계의 병목은 모델 변환이 아니라 여러
사용자의 실제 알림과 공통 행동 필요성 라벨이다.

## 선택한 출력 구조

처음 시도한 4개 클래스는 `INFORMATIONAL`을 한 번도 제대로 구분하지 못했다.
규칙 엔진이 이미 명시적인 광고 신호를 처리하므로 공통 모델은 다음 3개 의미만
예측하도록 단순화했다.

| 모델 클래스 | 학습 데이터 매핑 |
|---|---|
| `GENERAL` | `PROMOTIONAL` + `INFORMATIONAL` |
| `ATTENTION_WORTHY` | 직접 행동은 없어도 먼저 확인할 가치가 있음 |
| `ACTION_REQUIRED` | 사용자의 확인이나 행동이 필요함 |

기존 중요도 정책과 연결할 확률은 아래처럼 정의한다.

```text
important_probability
= P(ATTENTION_WORTHY) + P(ACTION_REQUIRED)
```

이 확률을 `docs/importance-policy.md`의 `-15 ~ +15` 보조 점수표에 넣는다.

## 학습 조건

- 모델: `monologg/koelectra-small-v3-discriminator`
- 데이터: v0.5 학습 가능 합성 알림 600개
- 분할: `template_group` 누수가 없는 고정 5-Fold
- 학습: 분류 헤드 3 epoch, 상위 encoder 4개 layer 12 epoch 미세조정
- 클래스 가중치: 역빈도 균형 가중치
- 최대 토큰 길이: 64

## 고정 5-Fold 결과

모든 OOF 예측을 한 번씩만 모아 계산한 결과다.

| 지표 | 값 |
|---|---:|
| 3단계 Accuracy | 0.863 |
| 3단계 Macro F1 | 0.859 |
| 이진 임계값 | 0.753454 |
| 이진 Accuracy | 0.915 |
| 이진 Precision | 0.927 |
| 이진 Recall | 0.913 |
| 이진 F1 | 0.920 |

3단계 confusion matrix는 다음과 같다. 행이 실제, 열이 예측이며 클래스 순서는
`GENERAL`, `ATTENTION_WORTHY`, `ACTION_REQUIRED`다.

```text
[[245, 17, 18],
 [  1,135,  6],
 [ 26, 14,138]]
```

Fold별 3단계 Accuracy가 `0.705 ~ 0.958`로 크게 흔들렸기 때문에 합성 데이터
안에서도 아직 문장군 의존성이 남아 있다.

## 최종 TFLite 산출물

교차검증 후 600개 전체를 학습해 FP32 TFLite로 변환했다.

- 파일 크기: 56,408,836 bytes, 약 53.8 MiB
- TensorFlow/TFLite logit 최대 절대 차이: `4.77e-7`
- TFLite builtin ops만 사용
- 모델 및 tokenizer 산출물은 Git에서 제외

변환 오차가 매우 작으므로 Python에서 학습한 분류기의 계산을 TFLite로 옮기는
경로 자체는 정상이다. 이 수치는 분류 정확도를 뜻하지 않는다.

### 후처리 양자화 비교

학습 완료 가중치에서 FP16과 동적 범위 양자화 모델도 만들었다. v0.5의 600개
문장 전체에 대해 FP32 모델과 비교한 변환 충실도다.

| 형식 | 크기 | 3단계 예측 일치 | 보조 점수 일치 | 중요 확률 최대 차이 |
|---|---:|---:|---:|---:|
| FP32 | 53.8 MiB | 기준 | 기준 | 기준 |
| FP16 | 27.0 MiB | 100% | 100% | 0.0000775 |
| 동적 범위 | 14.0 MiB | 100% | 100% | 0.0015892 |

기존 Room 12개에서도 두 양자화 모델의 3단계 예측은 FP32와 모두 같았다. 다만
동적 범위 모델은 경계에 있던 한 알림의 `-15` 점수를 `0`으로 바꿨다. 따라서
크기가 가장 작은 동적 범위 모델을 우선 Android 측정 후보로 삼되, 실제 기기의
새 홀드아웃에서 점수 경계 안정성까지 재검증한다. FP16은 더 보수적인 대안이다.

## 기존 Room 12개 개발 세트

이 사용자의 라벨은 중요 1개, 일반 11개다. 모델은 중요한 배송 1개를 놓치지
않았지만 일반 8개도 중요 후보로 올렸다.

| 지표 | 값 |
|---|---:|
| Accuracy | 0.333 |
| Precision | 0.111 |
| Recall | 1.000 |
| FP / FN | 8 / 0 |

중요한 해석상의 제한이 있다. 모델의 공통 정답은 `행동 필요성/확인 가치`이고,
Room 라벨은 한 사용자의 `중요/일반 선호`다. 따라서 모든 FP가 공통 의미에서도
오답이라고 단정할 수는 없다. 다만 현재 모델만으로 그 사용자의 중요도를 결정하면
알림을 과도하게 올린다는 제품상 실패는 분명하다.

로컬 Mac CPU의 참고 추론 시간은 median 3.43 ms, p95 47.30 ms였다. Android의
속도·메모리·배터리 값은 아니므로 실제 기기에서 별도로 측정해야 한다.

## 다음 통과 조건

1. 새 시점 또는 다른 사용자에게서 수집한 실제 REVIEW 알림을 학습과 분리한다.
2. 각 알림에 공통 actionability와 개인 선호를 별도 열로 라벨링한다.
3. 공통 모델은 actionability만 재학습하고, 개인 선호는 Android의 사용자 규칙과
   추후 경량 개인화 계층에서 처리한다.
4. 새 홀드아웃에서 전체 성능뿐 아니라 사용자별 FP, `ACTION_REQUIRED` FN,
   앱/이벤트 유형별 실패를 확인한다.
5. 통과 전에는 그림자 모드에서 예측만 저장하고 점수에는 반영하지 않는다.
