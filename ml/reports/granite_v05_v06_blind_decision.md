# Granite v0.5/v0.6 블라인드 비교 판정

## 결론

현재는 **v0.5를 잠정 유지하고 v0.6은 채택하지 않는다.**

모델 예측을 먼저 봉인한 뒤 실제 Room 알림 100개를 사람이 검수했다. 기존 개발용
40개 및 동일 전처리 문장 53개는 평가에서 제외했다.

| 지표 | v0.5 | v0.6 |
| --- | ---: | ---: |
| 3단계 정확도 | 90.0% | 87.0% |
| 등장 클래스 Macro F1 | 0.758 | 0.654 |
| 중요 Precision | 0.429 | 0.308 |
| 중요 Recall | 0.750 | 0.500 |
| 중요 F1 | 0.545 | 0.381 |
| 일반→중요 FP | 8 | 9 |
| 중요→일반 FN | 2 | 4 |

Kotlin 규칙과 결합한 개인 선호 이진 결과도 v0.5가 Accuracy 92.0%, F1 0.556으로
v0.6의 Accuracy 91.0%, F1 0.471보다 높았다.

## 통계적 해석

- v0.6-v0.5 정확도 차이: -3.0%p
- Paired bootstrap 95% CI: -8.0%p ~ +2.0%p
- McNemar exact p-value: 0.4531
- v0.6-v0.5 중요 F1 차이: -0.165
- 중요 F1 차이의 paired bootstrap 95% CI: -0.389 ~ +0.021

점 추정치는 모두 v0.5가 낫지만 신뢰구간이 0을 포함한다. 따라서 v0.5의 확정적
우월성을 주장하지 않고, 이 표본에서는 v0.6 개선 주장이 재현되지 않았다고 판정한다.

## 실패 원인

v0.6은 배송 진행을 일반으로 내리는 정책을 너무 넓게 적용했다. 일반 배송·배달
진행 오탐 일부는 고쳤지만, 사용자가 확인 가치가 있다고 본 배송 출발과 알람도
일반으로 내렸다. 광고·쿠폰·라이브 알림의 새 오탐도 생겼다.

즉, `배송 중` 전체를 하나의 공통 라벨로 고정하기보다 이벤트 세부 상태와 개인
선호를 분리해야 한다. 배송 출발·완료·회수는 공통 모델의 경계 사례로 유지하고,
사용자 피드백은 개인화 계층에서 별도로 반영하는 편이 안전하다.

## 한계와 다음 비교

- 실제 정답은 `GENERAL` 92개, `ATTENTION_WORTHY` 8개였다.
- `ACTION_REQUIRED` 정답이 없어서 세 클래스 전체 성능은 아직 검증되지 않았다.
- 한 사용자·한 기기의 알림이므로 전체 사용자 일반화 결과가 아니다.
- 이 100개를 보고 다음 데이터를 수정하면 더 이상 독립 테스트로 재사용하지 않는다.

다음 후보를 만들기 전 행동 필요 알림을 포함한 별도 challenge set을 수집하고,
수정 모델은 이후 새로 들어온 시간순 알림으로 다시 블라인드 평가한다.
